# 历史 PPO 训练轮次与验证吞吐

本图只展示已经完成的旧奖励实验；新“吞吐优先、移除 SLO”目标尚未开始训练，图中没有未来结果。

## 如何读图

- 横轴 0 为 BC 热启动模型（尚未做 PPO），1 为原 PPO 一个外层 epoch 后，2 为再训练一个外层 epoch 后。
- 一个外层 epoch 对同一条训练 trace 分别回放三个模型；每个模型抽一档负载，每条回放 1000 请求。
- 三条线对应随机种子 7、17、27；三幅子图对应 Qwen-1.8B、7B、14B。
- 验证固定为 `burstgpt_val_000000`（1000 请求），负载为各模型固定参考到达率的 0.5、0.75、1.0、1.25、1.5 倍。
- 相对图：每个种子以自身 BC 为 100%。先对每档负载计算 `当前吞吐 / 同条件 BC 吞吐`，再对五个比值取几何均值；越高表示相对自身 BC 越快。不能把不同种子的 100% 当作绝对吞吐相同。
- 绝对图：对五档负载的输出 token/s 取几何均值，用于比较三个种子的绝对水平。它是五个条件的汇总值，不是某一具体负载的实测吞吐；三个模型的纵轴范围不同。
- 连接线只连接已测检查点，没有 epoch 内或两点间的验证结果，不能据此推断中间单调提升。
- epoch 2 只继承旧权重，重新初始化 Adam/Torch RNG；其与 epoch 1 的差异不能仅归因于训练轮数。
- 全部数据是 FP16 decoder DAG 调度回放，不代表真实模型 tensor 推理；单条验证 trace 不足以证明泛化。

## 工件与复核

- `ppo_epoch_throughput_relative.png/.svg`：相对自身 BC 的吞吐曲线。
- `ppo_epoch_throughput_absolute.png/.svg`：绝对吞吐汇总曲线。
- `ppo_epoch_throughput_raw.csv`：135 行已测模型/种子/epoch/负载数据，保留 source_result 对应路径；不导出 SLO 字段。
- `ppo_epoch_throughput_aggregated.csv`：27 行模型/种子/epoch 聚合值及相邻检查点变化。
- 输入仅为 `comparison_cases.json` 与 BC/PPO/续训 PPO 对应的 `cases/*/result.json`；检查清单映射、三个种子、五档负载、请求数和吞吐=token数/总时间。
- PNG 为 300 dpi，SVG 保留可编辑文字；生成环境为本地 Python + matplotlib 3.9.2，字体 Arial。
- 本表采用几何均值，可能与之前报告的“逐条件百分比变化算术平均”有小幅差异；它们是不同聚合定义，不是原始数据变化。
