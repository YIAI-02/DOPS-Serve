# C026 原生 DOPS 训练前相关性实验：完整结果报告

报告日期：2026-09-11。结果目录：`pretraining_feature_screening_c026_dops`。

## 1. 结论与完成范围

**batch 是本轮最强的 placement 相关因素；prompt 也有明确的决策影响。计划生成长度 D 在 Prefill 中未观察到影响，在完整 Decode 中呈现较弱、依赖背景的影响。**

因此，未来输入应保留实际 batch 和 prompt/上下文长度信息。计划生成长度 D 暂列待确认，不能只根据很低的 Actor R² 就删除，也不能据此宣布必须增加一个独立的 max_tokens 输入。

本轮完成的是三个原始因素的控制变量实验，尚未完成 68 维 state / 23 维 node 的逐项筛选，也未完成在线状态及遗漏变量实验。以下没有使用旧错误批次的数据；没有训练监督网络、BC、Actor 或 Critic，没有计算 Critic R² 或另加输入价值指标。

## 2. 实验具体做了什么

### 固定配置与变化范围

| 项目 | 配置 |
|---|---|
| 模型 | Qwen-1.8B、Qwen-7B、Qwen-14B |
| batch B | 1、4、8、16 |
| prompt S | 128、512、1024、2048 |
| 计划生成长度 D | 128、256、512、1024 |
| 硬件与精度 | 1 NPU + 2 PIM，FP16，QKV/FFN TP=2 |
| 后端 | DOPS fast NPU / fast PIM，host/ND weights |
| 参考方法 | Bifocal C026，seed=7 |
| 调度参数 | lookahead 开启，H=2，gamma=0.4，consistency lambda=0.5，weight bias eta=0.5，plan hint max=3 |
| Decode 摊销参数 | 开启，alpha=1，minimum reuse=1，reuse probability=1 |
| Decode 计划刷新 | stride=2；按来源的真实调度/复用记录恢复 |

D 是一次请求计划生成多少 token，不是“当前已经生成到第几个 token”，也不是当前 KV/context 长度。

总计 3×4×4×4=192 个原始状态。每次只改变 B、S、D 中的一个因素，其余两个因素构成 16 个背景组。每个背景中，4 个目标状态与 4 个来源计划交叉运行，得到 4×4 成本矩阵。每个模型、因素、阶段有 256 个成本，其中 64 个自身比较，192 个非自身比较。

直接使用原生 DOPS 的 `SchedulerBase.schedule_with_plan`，保留 NPU/PIM0/PIM1、固定 KV 节点和执行顺序。没有经过 RL 二元动作转换器。

- Prefill：各候选从目标配置的相同冷状态出发。
- 完整 Decode：各候选从目标参考 Prefill 的相同结束状态出发，评价目标的全部 128/256/512/1024 个 token。
- Decode 计划按同一 token 序号对齐；若目标比来源长，超过来源长度的部分沿用来源最后一个计划。这是交叉评价规则，不能当成来源 DOPS 实际生成过更长的轨迹。
- 成本保留来源计划的设备分配和执行顺序；FlipRate 只计设备变化。成本变化不能全部归因于 device 选择，执行顺序也属于本轮比较对象。

C026 是冻结的参考，而不是数学上的全局最优。原始超参数扫描中，它在 168/192 场景快于其余八方法中的最佳者，24 个场景仍有其他方法更快。该扫描结果保留在原目录，不受旧相关性加载错误影响。

## 3. 三个数值分别是什么意思

### FlipRate：设备分配改变多少

Prefill 统计自由算子中 NPU/PIM0/PIM1 分配发生变化的比例。Decode 则统计目标全序列中的“自由算子 × token”变化比例。固定设备节点不进入分母；PIM0 换到 PIM1 也计为改变。

Qwen-1.8B/7B 各有 728 个自由节点，Qwen-14B 有 1,040 个。表中平均值是对 192 个非自身比较等权平均；最大值是其中一个比较的最大变化比例。

例如 FlipRate=0.5，报告写成 50%，表示该比较中一半自由算子的设备分配改变，不表示一半请求变慢。

### Regret：换用另一取值的计划后，阶段时间增加多少

$$
\mathrm{Regret}_{j\leftarrow k}
=\frac{T(A_k,x_j)-T(A_j,x_j)}{T(A_j,x_j)}
$$

两项时间均在同一个目标状态 $x_j$ 下得到；$A_j$ 是目标自身的 C026 计划，$A_k$ 来自同背景的另一因素取值。

- 0.10 = 10%：用来源计划后，该阶段时间是参考的 1.10 倍。
- 1.00 = 100%：时间变成 2 倍。
- -0.15 = -15%：来源计划反而比目标自己的 C026 计划快 15%。

平均 Regret 是 192 个有向迁移比较的算术平均，保留负值。不是线上平均吞吐损失，不是平均时间相除，也不是每次因素变化都产生这么多损失。最大 Regret 是本次网格内的最大值。

固定工作量时，时间增加 10% 对应吞吐减少约 9.09%，不能把 Regret 直接当吞吐下降百分比。Prefill 与 Decode 使用各自的评价初态，不能把两张表的百分比直接相加推导端到端吞吐。

### Actor R²：因素是否改变候选计划之间的相对成本关系

这里没有训练 Actor。使用 256 个成本的对数，通过固定的分组均值公式计算：

$$
R^2_{\mathrm{partial}}=
\frac{\mathrm{SSE}_{\mathrm{reduced}}-\mathrm{SSE}_{\mathrm{full}}}
{\mathrm{SSE}_{\mathrm{reduced}}}
$$

简化项包含“背景 + 目标因素取值 + 来源计划取值”；完整项再加入“目标取值 × 来源计划”的交互项。它先扣除所有候选一起变快/变慢等主效应，再看交互项能额外解释多少剩余变化。

例如 Qwen-7B 的 batch/Decode：简化 SSE=28.0048135067，完整 SSE=0.9494330020，所以 R²=0.966098，即交互项解释了简化项剩余误差的约 96.61%。**不是预测准确率 96.61%，不是 96.61% 的算子必须换设备，也不是解释了所有 placement 决策。**

不同背景共享一套交互项，因此只在少数背景出现、或方向不同的效应可能被总体 R² 淡化。R² 非零也不保证最快候选改变，故另核对成本矩阵中的最快候选集合。这里没有新增一个损失指标。

## 5. 哪些变化真的改变了最快候选

“最快集合变了”有时只表示原来并列的候选减少了，但仍有一份计划在全部取值下始终最快。报告因此检查四个最快集合是否存在共同候选。下表统计**没有共同最快候选**的背景数，分母均为 16；“最快”只相对于该组 4 个 C026 候选。

| 因素 / 阶段 | Qwen-1.8B | Qwen-7B | Qwen-14B |
|---|---:|---:|---:|
| batch / Prefill | 8 | 8 | 8 |
| prompt / Prefill | 8 | 8 | 8 |
| D / Prefill | 0 | 0 | 0 |
| batch / 完整 Decode | 16 | 16 | 16 |
| prompt / 完整 Decode | 16 | 16 | 14 |
| D / 完整 Decode | 3 | 7 | 9 |

若还要求同背景存在 FlipRate>0 且 Regret≥1% 的比较，D 的完整 Decode 背景数分别降至 **1、2、4**。这两个条件发生在同一背景，不等于证明任何共用计划都一定损失至少 1%；本报告不作这个更强的结论。

### 5.1 batch 的直接证据：改变 batch，最快计划随之改变

固定 Qwen-7B、prompt=128、decode=128，以下均为完整 Decode 秒数。列名表示来源计划是在什么 batch 下由 C026 生成的；所有列都会放到该行的目标 batch 中重新评价。

| 目标 batch | 来源 B=1 的计划 | 来源 B=4 的计划 | 来源 B=8 的计划 | 来源 B=16 的计划 |
|---:|---:|---:|---:|---:|
| 1 | **0.328293** | 0.585462 | 1.090746 | 1.484779 |
| 4 | 0.872788 | **0.750312** | 1.110791 | 1.480514 |
| 8 | 1.451012 | 1.350967 | **1.199859** | 1.353406 |
| 16 | 2.594623 | 2.415947 | 2.037761 | **1.519581** |

最快来源计划随目标 batch 依次为 1、4、8、16。目标 B=1 若使用来源 B=16 的计划，时间从 0.328293 秒增到 1.484779 秒，即增加 352.27%。这直接支持 batch 信息与 placement 决策有关。

### 5.3 为什么 D 只能给出有条件的结论

Qwen-14B、B=1、S=1024：

| 目标 D | 来源 D=128 的计划（秒） | 来源 D=256/512/1024 的计划（秒） | 最快来源 |
|---:|---:|---:|---|
| 128 | 0.711709 | 0.713710 | 128 |
| 256 | 1.038821 | 1.007093 | 256/512/1024 并列 |
| 512 | 1.699739 | 1.598361 | 256/512/1024 并列 |
| 1024 | 3.049490 | 2.799475 | 256/512/1024 并列 |

这里确实存在优劣反转。但短计划用于长目标时超过来源范围后冻结最后 placement，效应可能包括“继续随 token 演进的计划”与“冻结的计划”之间的差别。不能据此区分到底需要计划总长度 D，还是当前 token 进度/KV 长度已经足够。

另外，Qwen-1.8B、B=1、S=512 的最大 D-Regret 为 5.28%，但来源 D=512 的计划在所有四个目标长度下都最快。这个例子说明：**另一计划较差，不等于必须知道 D 才能选到最快计划。**

## 6. 负 Regret 与参考质量

负 Regret 没有截为 0。全体 3,456 个非自身比较中，402 个为负；其中 batch/prompt 的 Prefill 各 60 个，完整 Decode 中 batch 2 个、prompt 131 个、D 149 个。

例如 Qwen-7B、目标 B=4、S=128、D=128 的 Prefill：

- 目标自己的 C026 计划：0.363845659 秒。
- 来自 B=8 的 C026 计划：0.308543600 秒。
- Regret=-15.1993%，即来源计划更快约 15.20%。

这表明“目标自身 C026 计划”不一定是当前阶段候选中的最快者。可能涉及启发式搜索以及全请求目标与单阶段目标不同，单凭这条数据不能归因为随机不稳定，更不能说又发生了 PIM0/PIM1 映射错误。原始 192 个场景的自回放已全部完全匹配。

负值也会抵消正值，所以小平均 Regret 不能自动解释为处处无影响。附录提供中位数、阈值次数和负值次数。

## 7. 哪些算子、层和分片在变化

按 op type、四个连续层区间、shard 保留了 360 条分组统计。分组统计把非自身比较中的节点/token 合并后计算变化率，长 Decode 会有更大权重；这与主表“每个比较等权”的平均 FlipRate 口径不同。

以下是 Qwen-7B 的代表性算子结果：

| 改变因素 | 阶段 | 变化最明显的算子及该类型变化率 |
|---|---|---|
| batch | Prefill | SWIGLU 29.17%，W3 29.17%，W1 22.92% |
| prompt | Prefill | SWIGLU 29.17%，W3 29.17%，W1 22.92% |
| D | Prefill | 全部为 0 |
| batch | 完整 Decode | W3 76.54%，SWIGLU 74.61%，Q 73.31% |
| prompt | 完整 Decode | W3 33.89%，W1 27.69%，SWIGLU 21.63% |
| D | 完整 Decode | Q 15.06%，V 4.36%，K 4.30% |

Qwen-7B 完整 Decode 的四个层区间中，batch 的变化率为 49.45%–50.34%，prompt 为 10.13%–11.26%，D 为 1.75%–2.06%，变化并非只集中在少数层。batch 下 shard 0/1 的变化率分别为 48.57%/45.80%；shard 指张量分片编号，不是设备编号。

这些结果定位“变化发生在哪里”，不能直接当作 op-type、layer 或 shard 输入本身的独立相关性结论，因为本轮没有对这些因素做独立控制变量实验。附录 B/C 覆盖全部模型的层、分片和主要算子；完整分组记录位于 HPC 的 `operator_breakdown.csv`。

## 8. 对网络输入的直接建议

| 输入信息 | 本轮判断 | 依据与边界 |
|---|---|---|
| 实际 batch / 当前一起执行的请求数 | 保留相关信息 | 三模型、两个阶段均有明显影响，完整 Decode 证据最强 |
| prompt 长度 / 实际上下文长度 | 保留相关信息 | 有最优候选变化和实质时间损失；本轮直接干预的是 prompt，不是独立干预动态 KV 长度 |
| 计划生成长度 D / max_tokens | 暂列待确认，共享输入先不删除 | Prefill 无效应；Decode 弱且有条件，并受短来源轨迹外推规则影响 |
| 当前已生成 token 数、动态 KV/context | 尚不能单独下结论 | 与 D 不是同一变量，本轮未独立控制 |
| 68 维中的均值、最大值、分桶、归一化等编码 | 未决定逐维去留 | 一个原始因素会共同影响多维输入；本轮没有比较不同编码的信息冗余 |
| 设备尾部占用、KV/weight cache 历史、队列 age/到达率等 | 尚未验证 | 需要合法在线快照控制实验 |
