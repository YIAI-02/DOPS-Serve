# 二元 placement 转换对 BC/PPO 的影响核查

核查时间：2026-09-11 08:58 CST。范围：当前 HPC DOPS-Serve 的 PlacementCompiler、教师导入与重评分、BC/PPO 执行和 Static 对照；另对照 C026 实验现有的原始/转换后 Prefill 计时记录。本次是影响范围审计，复用已有实测对照和导入记录，没有新跑性能消融或修改训练实现，因此不将损失程度或唯一主因写成已证实。

## 已确认的结论

会影响实验。当前动作只表达 NPU 或节点预设 PIM；它不能完整表达原始 DOPS 的 NPU/PIM0/PIM1 选择。导入教师时会改变部分 PIM 身份，固定执行顺序也可能不同于原方案。本轮 BC 的教师因此是转换后的方案，不能称为原始 DOPS 优秀方案的完整复现。

这不等于发现了“改变动作后继续使用原始快耗时作标签”：本轮已经对转换后的方案在相同 anchor 上重新评分，BC 使用新 cost_s；PPO 的 reward 则来自实际编译后方案的回放。Static 同样在当前二元动作空间中选择和执行。当前成绩可作为该受限动作空间内的对照，不支持据此认定 PPO 在原始 DOPS 完整动作空间中无效。

## 转换实际做了什么

[placement_compiler.py:92](/Users/yangjiaqi/Desktop/Daily_2026/02_Projects/DOPSRT/DOPS-Serve/src/dops_serve/placement_compiler.py:92) 的 project 把 PIM0 和 PIM1 都记为 1；compile 在第 89 行将 1 解码为 pim_owner[node_id]，第 90 行统一使用 DAG 的固定拓扑顺序。

例如某个节点的预设 owner 为 PIM1：原始 PIM0 → 动作 1 → PIM1。与原始 PIM1 → 动作 1 → PIM1 得到同一个二元表示。原始设备身份已不可从这个动作恢复。

即使 PIM0/PIM1 硬件规格相同，改变个别算子所在设备也可能改变数据搬运、KV/权重位置、缓存复用和设备排队；这不是把两台设备的名字整体对调。

## C026 已有排查证据的界限

另一任务记录的配置为 C026。已有 prefill_reference_check.csv 中，F096（Qwen-7B、batch=8、prompt=128、decode=128）记录原始 Prefill 0.4510387026 秒，转换后评估 0.8179406641 秒，增加 81.346%。已有逐节点排查记录指出 28 个 FFN_W1_s1 节点从 PIM0 变为 PIM1。

这份相关性实验报告现已标记为无效、撤回输入筛选结论；该计时差和节点变化只用作排查证据。其原始 C026 超参数扫描与这个错误转换的相关性实验分开保存。

没有新的控制变量结果证明全部 81.346% 都由 PIM 身份改变导致；执行顺序、初始状态和其他评估差异尚未分别排除。它是 Prefill 阶段耗时变化，不是完整生成吞吐的下降比例，也不能套用成当前 BC/PPO 全部实验的损失比例。

## 调用路径与现有成绩能说明什么

| 环节 | 当前实现 | 影响 |
|---|---|---|
| 教师导入 | placement_dataset.py:108–110，先 project 再 compile | 原始 PIM 身份可能丢失；原始顺序被固定顺序替代 |
| 教师重评分 | placement_dataset.py:210–211，评价转换后 fixed_plan 并写 cost_s | 成本标签对应实际转换后方案，不能恢复已失去的优质原始安排 |
| BC 更新 | placement_training.py:122–128，按新 cost_s 加权拟合 block_actions | 学习的是受限空间内的教师分布 |
| BC/PPO 产生安排 | placement_policy.py:145–147，二元动作直接 compile | 网络无法提出预设 owner 之外的 PIM 选择 |
| 执行检查 | placement_evaluator.py:167–171 | 非规范 owner 的输入会报错；合法二元方案不会在这里被悄悄再次改变 |
| Static | placement_evaluation.py:50–58、96–175 | 候选也源于投影后的教师，按同一动作空间回放选择 |

这是一项设计中的限制，而非单纯遗留的未删除代码：tests/test_placement_compiler.py:41–47 明确检查了自由节点 PIM1 会被投影回预设 PIM0。该测试验证了预设合同，没有验证原始 DOPS placement 的保真性或性能损失。

此前应当量化并明确报告这个简化对教师性能的影响；只记录 projected_pim_changes 并做转换后重评分，不足以证明这个简化代价可接受。

Static 在同一受限空间内仍能优于 BC，说明至少存在当前网络可以表达的较好方案。转换限制可能影响教师质量与可达到的性能，但不能单独解释训练未学会 Static、种子差异或后期退步；本次未证明它是唯一原因。

## 最小后续验证与修正方向

1. 先在同一后端、相同工作量与起始状态下，对照三种执行：原始设备+原始顺序；原始设备+固定顺序；二元转换后设备+固定顺序。先覆盖已暴露差异的 F096，再扩展到各模型及完整 decode。分开量化顺序与设备身份的代价。
2. 原始 DOPS 参考回放采用保真接口，逐节点核对设备和顺序；不能先 project 再以转换结果通过自身规范检查来声称保真。
3. 若目标是让 RL 学会原始 C026 的设备分配，自由节点需要表达 NPU/PIM0/PIM1（保留真实合法性与 KV 约束），或另用经验证等价的表示。单纯增加 epoch 或网络层数无法恢复动作中被删除的 PIM 身份。
4. 若扩展动作空间，应同步修改动作 mask、输出头、动作 embedding、编译与验证；重新生成 BC 标签、重评分、选择 Static 并校准奖励，再训练新的 BC/PPO。旧二元检查点保留为受限方案对照，不能当成无缝兼容的续训结果。

本次没有改变现有训练参数、提交器规则、自动化或其他实验作业。当前 95% Static 门槛的内部比较口径仍保留，但不可将通过/未通过解释为对原始 DOPS 完整动作空间的最终结论。
