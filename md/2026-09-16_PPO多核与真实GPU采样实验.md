# PPO 多核与真实 GPU 采样实验

## 目标与边界

- 在本次实验总计不超过 64 CPU 核的条件下，测量多进程回放与真实多环境 GPU 合批采样的收益。
- 沿用 BC E0、独立模型 best critic、既有标定及 BurstGPT 连续到达/排队。正式 PPO、训练协议和 checkpoint 不修改。
- 使用已讨论的 32 条完整 train trace，各运行 0.5/1/1.5 三种负载，共 96 个任务；不使用 val/test。

## 执行

1. CPU：7B，比较 12/24/48/60 进程；每进程单线程，每任务预热 8 plan 后测 64 plan。两轮顺序相反，固定任务及每任务随机流，传回真实 rollout 分块。
2. GPU：为 CPU 最快的两档补测 GPU 批量采样，上限 16/32/60；先在同一 GPU 节点重测对应 CPU 基线，避免节点差异混入加速比。实际输入来自不同环境，包含 IPC、构造张量、拷贝、组批等待和动作返回。使用严格 FP32。
3. GPU 网络使用每环境预生成的独立均匀随机数做分类逆 CDF 采样，避免进程数/到达顺序改变随机数分配；此接口仅用于实验。检查同动作 logits/value 和动作合法性。
4. GPU 模式由 CPU 保留完整模拟状态，主进程保留 old log-prob/value，按环境独立计算每个 16-plan 分块回报。所有采样使用同一冻结策略版本。
5. 取一条 trace 的三个负载片段进行一次现有 PPO pass，测真实采样数据接入 GPU 更新；临时权重丢弃。该更新仍使用现有 pass 末 KL 检查，不宣称已完成正式训练改造。
6. 最佳 GPU 配置在 1.8B/14B 上短验证。报告启动时间、回放总时间、实际批大小、等待/传输/网络时间、CPU/GPU 利用率、内存、更新耗时及覆盖的 batch/KV/阶段。

## 最小验收

- 所有配置工作量一致；CPU 两轮逐任务动作/模拟结果一致。GPU 检查同动作网络数值和合法性，记录浮点差异是否导致回放动作分歧。
- 性能选择以实际完成相同任务的总耗时为主；GPU 利用率只是诊断指标。
- 片段测速与一次更新接线不等于完整 50 epoch 耗时或收敛验证；正式环境数、每轮采样量及恢复边界仍待实验后确定。

## CPU 完整结果

每格均为相同 96 个任务、6,144 个测量 plan、384 个真实 rollout 分块。计时包含任务初始化、每任务 8 plan 预热和分块传输，不含进程池启动；单次启动约 1.6–2.8 秒。

| 进程数 | 第一轮 / 秒 | 第二轮 / 秒 | 均值 / 秒 | 相对 12 进程 |
|---:|---:|---:|---:|---:|
| 12 | 323.18 | 323.04 | 323.11 | 1.00× |
| 24 | 176.10 | 176.20 | 176.15 | 1.83× |
| 48 | 97.19 | 96.81 | 97.00 | 3.33× |
| 60 | 92.99 | 93.52 | 93.26 | 3.46× |

- 两轮所有配置的逐任务动作序列、模拟时间、输出 token 和完成请求数一致。
- 60 比 48 多用 25% 的回放进程，只增加约 4.0% 速度、减少约 3.9% 耗时。后续 CPU 回放优先考虑 48 进程；这只是资源建议，不自动改变 PPO 每轮采样量。
- 此处比较的是实验中的独立随机流/CDF 采样器。未将生产代码的 `torch.multinomial` 采样器改写，也未验证完整 50 epoch 耗时或收敛。
