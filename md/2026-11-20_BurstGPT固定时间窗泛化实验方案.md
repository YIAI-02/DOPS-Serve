## 1. 目标与实验矩阵

主实验检验冻结模型在真实新长度、混长批次和未训练过的 batch size 上的放置效果；补充实验检验同一批次清单加入到达、组批和设备排队后的服务表现。数据仅使用 BurstGPT 的长度和时间戳，不使用真实文本生成，不更新 PPO 权重。

| 项目 | 已确认设置 |
| --- | --- |
| 正式数据 | 新选 16 段连续请求，每段 512 条，共 8,192 条；旧 2,048 条样本及其泛化结果作废，不再用于诊断或回归 |
| 输入限制 | 输入 token 数不超过 8192；保留实际输入/输出配对，不截断或补齐原始记录中的长度 |
| 组批时间窗 | 固定 1 秒，窗口结束后形成待执行批次 |
| 到达率 | 原速、10 倍、20 倍、50 倍；到达间隔分别乘 1、0.1、0.05、0.02 |
| 实际 batch | 1–16 任意整数；同窗超过 16 条时，按到达顺序分成多个批次 |
| PPO 模型 | A/B/C/D 各选 1 个 Final seed，共 4 个；在各自三个 seed 中按原 196 工况成绩选优 |
| 比较基线 | PD（prefill NPU / decode PIM）、全 NPU、全 PIM、固定参数 Bifocal |
| 主指标 | 相对 PD 的总模拟服务耗时降幅；同时报告单批耗时 P50/P95 和逐批胜率 |
| 算法 CPU 开销 | PPO 推理与 Bifocal 搜索的 CPU 耗时均不纳入本轮结果 |

共 8 种方法 × 4 档到达率，形成 32 组汇总结果。每组都重放同一份 8,192 条原始请求；不同到达率需要重新组批，同一到达率下所有方法的批次清单完全相同。

## 2. 数据抽取与固定时间窗

来源为 `BurstGPT_without_fails_1.csv`。已检查的本地完整缓存有 1,404,294 条有效记录，时间戳全部为整数秒；输入超过 8192 的记录为 105 条，占约 0.0075%。过滤后长度合格库为 1,404,189 条。输出范围为 1–7,315，保留短于训练最短输出 64 的真实请求。

旧 2,048 条就是上次泛化实验的 8 段 × 256 条。上次按固定目标 batch 凑满的回放设置，与本轮确认的“固定 1 秒窗结束就组批”不同，因此撤下旧样本及旧泛化结论。清理对象是派生测试文件和结果，不修改原始完整 CSV，也不将原始请求判为无效数据。

抽样执行细则：

1. 保留原 CSV 行号，以时间戳、原行号排序；先过滤输入超过 8192 的记录，保留剩余请求的原始时间间隔。
2. 将过滤后的记录序列按顺序分成 16 个大小尽量相等的区段；固定随机种子 `20261120`，每段随机选一个包含 512 条连续合格记录的片段。
3. 所有新片段互不重叠、无重复原行号，并继续满足已确认的“使用新记录”。若候选片段与下述已用行号区间相交，则在该区段重新抽取；无需读取或保留旧样本文件。片段的“连续”指过滤后的序列；如中间存在被过滤记录，时间差仍保留。
4. 在正式策略评估前保存并固定清单。报告抽样后的长度分布、实际到达率和实际 batch 分布；不根据策略成绩更换样本或均衡长短请求。

仅保留以下已用行号区间作为抽样排除元数据：`441172–441427`、`448976–449231`、`675188–675443`、`708206–708461`、`849375–849630`、`1058742–1058997`、`1334152–1334407`、`1358835–1359090`。均为原 CSV 去掉表头后从 0 开始的 `source_row`，两端包含；合计 2,048 行。不保留这些请求的长度、到达轨迹或旧评估成绩作测试输入。

每个片段独立从首条请求到达时刻归零。对倍率 `r ∈ {1,10,20,50}`，缩放后的到达时间为 `a=(原时间−片段首时间)/r`。按半开区间 `[k,k+1)` 组批，时间恰好落在整数边界的请求属于新窗口，批次的就绪时刻为 `k+1`。原时间为整数秒，可用整数除法确定窗口，避免浮点边界漂移。

- 同窗 36 条请求形成 `16、16、4` 三批，三批均在同一个窗口末尾就绪，内部保持原到达顺序。
- 空时间窗跳过。设备繁忙时，已经形成的批次进入 FCFS 队列，不与后续窗口重新合批。
- 片段结尾仍按最后一个组批窗口的正常结束时刻闭合，再排空队列；不提前释放尾批。
- 同刻请求保持相同时间戳，以原行号稳定排序。倍率是人为时间缩放，不据此声称恢复了原始毫秒级到达过程。

## 3. 执行、选模与基线合同

沿用现有 Qwen-1.8B、28 层、FP16、1 NPU + 2 PIM 的解析模拟器，以及此前确认的执行近似：

- 每批按 `P=max(输入长度)`、`D=max(输出长度)`、`B=实际请求数` 执行；两项最大值可能来自不同请求。
- 每批冷启动，设备占用至最长输出结束。短请求按自身输出长度对应的 token 前缀记完成，但不提前缩小执行 batch，也不补入新请求。
- 策略已知该批的目标输出长度；decode 放置刷新间隔为 `min(256, ceil(D/16))`，每个实际 token 仍推进执行和 KV 状态。
- PPO 使用确定性预测。A/C 的时间观测继续使用同形状全 NPU 耗时归一化；该参考曲线预先计算，保持训练时的观测含义。

正式选模在本轮训练及原生重载验收完成后进行。A/B 各 seed 为 1,244,160 步，C/D 各 seed 目标为 1,002,240 步；分别在每种方案的三个 Final 中取 `summary.final.normalized_latency` 最低者，精确并列时取 seed 较小者。冻结四个模型及配置到新目录，记录全部候选分数和实际训练预算。新 BurstGPT 成绩不参与选 seed、选检查点或训练调整。

Bifocal 固定使用 `SB3_PPO/runs/bifocal_grid196_20261119/best_shared_params.json`，即此前选出的 `h2_g0.5_p64_d512` 共用参数；完整参数文件原样保存。每个新形状按该参数搜索生成计划，保留跨层细粒度节点顺序与设备放置，不迁移或事后修改生成计划，不在新数据上重新选参。其放置刷新间隔与 PPO 相同；固定远期评分窗口仍为 prefill 64、decode 512，不替换成真实剩余输出长度。

每个唯一形状和方法的服务曲线可以计算一次后复用；汇总时必须按该形状在各档负载中实际出现的批次数累加，不能将去重后的形状等权平均。

## 4. 指标与报告口径

对每一档到达率，令 `S(m,b)` 为方法 m 执行批次 b 的完整模拟服务耗时：

`总服务耗时降幅(m) = 1 − Σ_b S(m,b) / Σ_b S(PD,b)`。

总服务耗时包含模拟器中的计算、通信和执行资源等待，不包含请求到达间隔、组批等待、批次排队或算法 CPU 时间。正值为改善，负值为变差。报告各方法总耗时、相对 PD 降幅、prefill/decode 耗时分解、单批 P50/P95、逐批胜率，并按实际 batch 和长度区间给出描述性分项。主结论保留样本中的实际请求分布。

补充在线回放使用 `start=max(批次就绪时刻, 上批释放设备时刻)`。对每条请求分别记录：

- 组批等待：批次就绪时刻减请求到达时刻；
- 设备排队：批次开始时刻减就绪时刻；
- TTFT：开始时刻加首个 decode token 前缀耗时，再减请求到达时刻；
- E2E：开始时刻加该请求输出长度的前缀耗时，再减请求到达时刻。

逐请求统计上述 P50/P95，另报告完成全部片段的真实输出 token 吞吐。吞吐分子使用各请求实际输出 token 总数，分母为 16 个片段各自从首到达到排空的总耗时之和，包含到达空闲与等待，因此不解释为硬件峰值吞吐。保留每个片段的指标，避免只给一个混合汇总值。

报告四个选定模型的单模型结果，不将其误写成三个 seed 的均值或种子稳定性结论；分别注明 A/B 与 C/D 的训练预算。只支持本次长度、实际 batch、固定窗规则及冷启动近似下的结论，不宣称在线未知 EOS、持续热缓存服务或 PPO 根据队列自适应。
