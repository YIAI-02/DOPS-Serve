# 基于 BC 初始化的 BurstGPT PPO 优化方案（导师汇报版）

2026-09-14。本文概括实验设计；实施信息依据本地方案、protocol.json 和启动记录，不代表实时作业状态或已取得性能提升。

## 1. 研究目标与实验路线

在已有 BC 算子放置策略上继续进行 PPO 训练，让策略适应 BurstGPT 中的连续请求到达、排队和动态 batch，并直接优化端到端模拟吞吐。

- **优化对象**：每个可学习算子放在 NPU、PIM0 或 PIM1 上执行。请求采用 FIFO 准入，PPO 不直接选择请求顺序。
- **硬件口径**：C026，1 NPU＋2 PIM，FP16，QKV/FFN 的 TP=2，沿用 BC 的 fast/fast 成本与 overlap 配置。
- **四条路线**：Qwen-1.8B、7B、14B 各一个独立策略，另训练一个三模型共享策略。同一请求数据分别用于三个模型的模拟回放。
- **BC 起点**：1.8B E57、7B E77、14B E42、共享 E35。

选择 PPO 的考虑是：一次放置决策会影响后续执行时间、缓存状态和排队，需要评价连续决策的长期收益。方案采用独立 critic 估计后续时间成本，并用 PPO 限制策略单次更新幅度；目前不预设它在本任务上优于 GRPO。

## 2. 数据、负载与服务过程

**数据划分。** 使用 BurstGPT_without_fails_1.csv 的全部 1,404,294 条请求，保留原始长度、类型和重复行。按时间稳定排序，以 70%/15%/15% 划分 train/val/test，分别为 983,005/210,644/210,645 条请求。

每连续 1,000 条请求组成一个 trace，即一次独立的请求回放实验；不足 1,000 条的末段也保留。因此三部分分别有 984/211/211 条 trace，末段含 5/644/645 个请求。每条 trace 从空队列、空 KV 和相同初始缓存开始，保留内部到达顺序与间隔，直到全部请求完成。

**三档负载。** 在训练区用 PD 基线的饱和回放估计每个模型的参考输出吞吐 S_m。设训练区原始输出工作量到达率为 A，将到达间隔统一乘：

`A / (负载系数 × S_m)`，负载系数取 0.5、1、1.5。

其含义是让训练区平均到达工作量约为参考处理能力的 50%、100%、150%，同时保留原有突发变化。1× 表示 PD 参考容量，不表示原始时间间隔或硬件利用率。缩放系数固定用于 val/test，不根据验证和测试数据重新标定；它们的实际负载可能偏离名义档位。

**准入与 KV。** 最大并发请求数为 16。统一公开 `max_tokens=7315`，按每个请求的 `prompt_len+7315` 预留 KV；容量不足则排队，完成后释放。保留最大输入 29,665，对应单请求最多预留 36,980 个 token。两块 PIM 的 runtime 总预算约 30.4 GiB，权重、激活和 KV 共享；先导配置每块 PIM 留 1 GiB 非 KV 余量，容量压力检查详见启动记录。

真实输出长度仅用于环境判断请求何时完成，不能进入 actor、critic、准入或提前成本预测。

## 3. 如何从 BC 继续训练

**网络继承。** 保留 BC 的两套四层、宽度 256 的 state/node 编码器、GRU256 和三设备动作头。state 从 47 维扩为 56 维，第一层原有 47 列权重和偏置复制，新增 9 列置零；node 仍为 35 维。迁移后保留冻结副本 E0 作为基线，PPO 更新其可训练副本。无需额外 BC 适配训练，也不加入教师模仿损失。

**state：描述当前服务状态。**

- 原前五项适配为：本次 phase 的实际请求数、平均 prompt、固定的 BC 训练集已缩放 decode 特征均值、平均 generated−1、平均已写入 KV 长度。prefill 的后两项为零。
- 保留 phase、模型结构、设备可用时间、缓存/内存、通信状态和 KV 放置位置；旧 KV 记账槽位维持原语义，实际已写 KV 从请求台账读取。
- 新增九项：公开输出上限、排队数、已准入未完成请求数、平均/最大等待时间、当前 phase 的 prompt 最大值/标准差、decode KV 长度最大值/标准差。空等待统计和 prefill 历史 KV 统计为零。
- 保留原特征缩放。未来输出长度这一旧输入改为常数，避免策略使用实际服务时不可获得的信息。

**node：描述当前算子。** 每个节点 35 维，包含算子类型、层/拓扑位置、分片编号、权重大小、计算工作量、Q/KV 头数和 FFN 维度、三设备缓存与合法性、最近实际执行的 prefill/decode 放置。工作量按各请求真实可见长度求和：prefill 的 token 数为 ΣP_i、attention 配对数为 ΣP_i(P_i+1)/2；decode 分别为当前请求数、Σ(kv_len_i+1)。

state 编码提供 GRU 初始状态；节点编码结合此前节点已选设备，依次产生当前节点的设备动作。新增输入初始权重为零，但旧特征改为动态统计仍可能改变行为，因此先评价 E0，再计算 PPO 的额外收益。

## 4. 决策、奖励与 PPO 更新

**执行循环。** 请求到达入队 → 按容量准入 → 根据实际执行请求构造输入 → 生成或复用放置计划 → 模拟执行 → 更新输出与 KV → 完成后释放。沿用三设备身份、拓扑和合法跟随规则。

每次 prefill 生成新计划并产生首 token，之后执行 output_len−1 次 decode。请求加入、退出或发生新 prefill 时重置局部刷新计数，按 0、1、2、4、6… 刷新 decode 计划，其余步复用。刷新计数与请求自身生成进度分开。

**动作与奖励。** 训练时按概率采样 NPU/PIM0/PIM1，评价时选最大概率动作；固定或跟随节点参与 GRU 历史，但不计随机动作损失。每次执行至下一决策的奖励为：

`r = −Δt / C_m`

Δt 是该段模拟耗时；C_m 是训练区 PD 饱和回放的平均 trace 耗时，用于模型间尺度归一化，同一模型三负载共用并冻结。对同一条请求 trace，总输出量固定，缩短完整耗时就能提高吞吐。计划内部选节点不推进模拟时间，时间奖励记在该计划最后一个可学习动作之后；空闲及最后排空耗时也计入。

**critic 与回报。** critic 独立复制 BC 编码器和 GRU，新增标量价值头，估计后续归一化负时间回报；只在训练时使用，价值损失不更新 actor。取 γ=λ=1；采样截断时用下一真实 phase 的旧 critic 价值补齐后续回报，trace 真正结束时补零。

**采样与更新。** 每个环境每段最多采集 16 次完整计划刷新，更新后保留环境继续回放。独立策略同时覆盖三个负载组，共享策略覆盖九个模型×负载组；每批组内节点损失取均值，组系数固定为 1/3 或 1/9。提前完成的组停止采样，全部组完成当前源 trace 后才换下一条；组系数相同不保证累计梯度贡献完全相同。

PPO 重放实际采样的动作前缀，逐节点计算新旧条件概率比，以截断目标限制更新；优势按组标准化，actor 加熵项，critic 使用回报均方误差。每组 mini-batch 起步为四份完整计划。

| 参数 | 起步值 |
|---|---|
| Actor / critic 学习率 | 3e-5 / 1e-4；两份独立 Adam |
| PPO clip / 每批更新遍数 | 0.1 / 最多 4 遍 |
| 新旧策略平均 KL 停止阈值 / 熵系数 | 0.01 / 0.001 |
| 梯度范数上限 | 0.5 |

## 5. 如何证明训练有效

**主要指标。** 每个模型×负载组合使用 `Σ输出 token / Σ完整 trace 模拟耗时`，时间包含空闲和最终排空；策略决策 CPU 耗时单独报告。E0、PD、PPO 使用相同请求和执行口径。

**训练覆盖与随机性。** 训练 trace 无放回打乱循环，至少完整覆盖一轮及全部三档负载。独立策略每轮每种子 2,952 个 trace 任务，共享策略 8,856 个；四路线×三种子合计 53,136 个任务/轮。先导使用 seed=7；正式使用 7/17/27，共 12 次训练。种子改变 trace 顺序、动作采样及新增参数初始化，不改变源数据划分或 trace 内请求顺序；正式训练均重新从相同 E0 起步。

**选模。** 约每完成 10% 覆盖及轮末，用固定 16 条 val trace 快速验证。每路线/种子的前三个 PPO 检查点与 E0，再用全部 211 条 val 重评选定；之后才在全部 211 条 test 上报告最终结果，测试集不用于调参。

**评分与结论。** 独立策略取三个负载、共享策略取九个模型×负载的相对 E0 吞吐比的等权几何均值。目标为三个种子的平均综合吞吐比大于 1；同时报告每个种子、每组结果、均值与标准差，保留退化及 E0 获选的情况。另报相对 PD 吞吐、请求延迟、决策开销、峰值内存和训练成本。
